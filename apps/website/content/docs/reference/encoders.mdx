## Catalogue

The catalogue is the set of encoder families the build knows. Each family has a stable key, a label, a default executable, and a generated parameter schema. A fork of a family appears under that family; it does not create a new schema.

## Provider

The provider panel chooses the executable for a family. A bundled path, a system path, or a user-located path can provide it. The picked path is probed for a version before it is accepted. A rejected path is not saved.

## Parameter table

<LiveWidget id="W05" />

| Column | Meaning |
| --- | --- |
| Label | The human name from the schema |
| Flag | The executable's spelling of the parameter |
| Value | The current draft value, or the executable default |
| Set | Whether the draft differs from the executable default |

Search matches the label, flag, and description. The header counts descriptors, and **Add parameter** opens the sheet for a parameter the table does not list.

## Editor sheet

The sheet edits one parameter with the control its type requires: number with bounds, choice, switch, text, or structured value. Validation is inline; Apply writes the draft, Cancel discards it. A value outside the schema is refused, not coerced.

## JSON

The JSON view edits the serialized descriptor document. The contract is checked on every edit, and Save stays disabled until the editor can render it. **Import** replaces the document from a file and **Export** saves a copy, so the view is also useful for support and for comparing two builds' documents.

## Saved builds

| Field | Meaning |
| --- | --- |
| Name | The selector label |
| Family | The parameter schema and probe behaviour |
| Executable | The probed binary |
| Version | The parsed version, or unknown if unparsable |

A saved build whose executable disappears remains listed but unavailable. Selecting it refuses the run with the build's name.

## Fork profiles

Two SVT-AV1 forks ship with a complete parameter table but no executable: **SVT-AV1-Essential** (the 4.3.0 pre-release line) and **SVT-AV1-5Fish** (rolling). They are not bundled builds. Add the fork's executable in Settings → Encoders; the profile is detected from its `--full-help` output and the shipped table is applied to the saved row.

A known fork row has a fixed label and cannot be renamed or deleted. **Clear executable** forgets the path, leaves the row resolving on `PATH`, and reports the base encoder's availability; **Reset parameters** restores the shipped table without touching the path. If the executable does not show the profile's signature flags, the row keeps the table and shows a warning instead of rejecting the build; the check is lenient because a fork can rename or rebuild itself.

The table is independent of the executable's version. Help still decides which flags exist and what their defaults are: a flag absent from the help disappears, a new flag is added as an advanced row, and a flag the table does not know is typed generically. When a build shows both signatures, 5Fish wins because it incorporates features from the other forks.

## Overrides

A project's Encoding document applies to every video without its own. A video override replaces the whole document. A per-scene encoder applies to exactly the selected scenes and is carried in their chunks' fingerprint.

## States

| State | Meaning |
| --- | --- |
| Loading | The catalogue or probe is in flight |
| Ready | The family and provider are usable |
| Probe failed | The executable could not be run or parsed |
| Version unknown | The probe ran but the version did not parse |
| Build unavailable | A saved build's executable is missing |
| Invalid | The document fails the schema |
