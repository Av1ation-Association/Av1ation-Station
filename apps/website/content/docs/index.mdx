The public manual is the end-user guide to the current `0.1.0-rc.3` pre-release. It explains what the application does, how its settings fit together, and how to recover when a run does not. Architecture, contracts, and contribution rules live in the repository and are linked from [For contributors](/docs/contributing).

## Start here

If you have not installed the application, begin with [Install and verify](/docs/get-started/install). If it is already running, [Your first project and encode](/docs/get-started/first-encode) walks one video from the queue to a readable output.

</Callout>

## Understand the pipeline

Av1ation Station is a desktop workspace around a scene-aware encode. The pipeline has six stages: scene detection, optional noise generation, optional target quality, parallel encoding, concatenation, and an optional quality check. Each stage writes its own data, so the current state is read from that data rather than stored separately.

<Callout tone="note" title="One project, many videos">
A project owns shared configuration and a queue. Each video inherits that configuration until it overrides a whole section. The queue runs one video at a time; the encode lock is process-wide.
</Callout>

Read [How the pipeline works](/docs/concepts/pipeline) for what each stage produces, and [Configuration and inheritance](/docs/concepts/configuration) for why a video override is complete rather than a patch.

## Get help

The [troubleshooting pages](/docs/troubleshooting/dependencies) start from a symptom. When the application cannot explain a failure itself, follow [Diagnostics and support](/docs/troubleshooting/support) before sharing a log: exported evidence is redacted, but screenshots and project files may not be.

## What this covers

This manual documents the surfaces a user can reach in `0.1.0-rc.3`: Projects, a project queue, video configuration and scenes, History and Logs, Settings, project templates, encoders, filters, the script data module, and keyboard shortcuts. It does not document unused API routes, future features, or a migration workflow the release does not provide.

<Callout tone="warning" title="Pre-release">
Windows and Linux installers are unsigned; the macOS build is ad-hoc signed and not notarised. The application is usable for real encodes, but keep backups of project files you care about.
</Callout>
