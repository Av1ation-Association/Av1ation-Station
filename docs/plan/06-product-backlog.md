# Phase 6 — Product backlog

> **Planning record.** Current delivery status lives in [progress.md](../progress.md).

**Status:** active planning and first fixes. This is the working catalog for the issues reported
after the bundled-toolchain release candidate. It is also the **first-stable gate**: every
remaining item must be completed, or explicitly deferred with a reviewed reason, before a
stable tag. The RC channel remains available while this work proceeds. Update the Status
column as work lands; keep the verification column honest even when a check is deferred.

The list came in unordered. It is grouped below by the part of the product that owns the
decision, then ordered by what should be fixed first. Priority means product risk, not
difficulty: a P0 can corrupt a run or make an installer unusable, while a P2 is a polish or
investigation item.

## Priority meanings

| Priority | Meaning |
| --- | --- |
| **P0** | Blocks a trustworthy release, loses work/data, or makes the installed app fail to launch. |
| **P1** | A frequent workflow is wrong or an important capability is misleading; fix in the next feature batch. |
| **P2** | Polish, consistency, performance, or a research question that can wait without hiding a failure. |

## Stable gate

The first stable release waits for this catalog to be closed. Closing an item means it has
the verification recorded in its row, not merely an implementation commit; an item that is
deliberately left out is marked deferred with the reason and the release that owns it. The
RC channel is not blocked by this gate, so release-candidate feedback can still be gathered
while the remaining work lands. The Phase 5 package and installer evidence remains a
separate requirement; neither gate substitutes for the other.

### B5 tooltip inventory

Scanned every JSX `<button>` under `packages/ui/src` with the TypeScript AST on 2026-11-18 and reviewed the remaining `data-tip`, `title`, and `aria-label` call sites.

| Pattern | Inventory | Decision |
| --- | --- | --- |
| Visible text already names the action | Log sort headers, FilterList's edit button, SectionMenu, the queue's **More**, the encoder path **Browse**, and ordinary labelled `Button`s | No tooltip; a bubble would repeat the label. |
| Icon-only action | Close, clear-search, remove, move, expand, fullscreen, mute, template-default/delete, queue-actions, numeric stepper, rename/save/cancel, pairing-copy, and schema-array remove controls | Each has both `aria-label` and `data-tip`; right-edge controls use `data-tip-align="end"`, and controls on a clipped bottom edge use the pane's `data-tips="up"` or `data-tip-placement="up"`. |
| Expanding compact action | `RemoveButton`, `SequenceActionButton`, `RunControl`, `TopBarButton` | The label expands on hover and keyboard focus, so a second bubble would repeat it. A `data-tip` remains where it adds a disabled reason or shortcut. |
| Click/focus documentation | `InfoPopover`, `ParameterPreview`, `ParameterValueGrid` | The info control opens a documentation panel on hover, click, or keyboard focus; a bubble would compete with that panel. |
| Disabled reason | Shared `Button` with `title`/`data-tip`, `RunControl` with `disabledReason`, `TopBarButton` with `hint` | A hinted disabled action keeps hit-testing so the bubble can open; the native `disabled` attribute still refuses the click. An unhinted disabled action keeps `disabled:pointer-events-none`, so it cannot swallow a row click. |
| Keyboard reachability | Enabled controls everywhere; native disabled controls | `:focus-visible` opens every enabled tooltip. Native disabled buttons are outside the tab order, so a disabled reason remains pointer-only; the adjacent explanatory copy or the action's accessible name is the keyboard path. Making disabled controls focusable would need an `aria-disabled` refactor and is left as a follow-up. |

Delay and placement are shared: the base `[data-tip]` pseudo-element opens on `:hover` and `:focus-visible` with the instant motion token, suppresses animation under reduced motion, and clamps its width without adding a DOM node.
